# 高质量中文识别

## 原状

用户在 +21 上复测后仍遇到形近字错误和乱序。去掉重复转写与放大图片不能解决原模型对手写风格字体的识别误差。

## 本轮范围

高质量 Bitmap/URI 入口保留 ML Kit 文字行定位，改由 PP-OCRv5 移动识别模型读取各行原始像素。输入带少量边距，保持颜色，不做阈值化、词表替换或语义补写；行序按屏幕位置排列。普通速度模式及显式语言入口保持原有行为。

识别模型固定为 RapidAI 的 ch_PP-OCRv5_rec_mobile.onnx，来源版本 v3.9.2，16631306 字节，SHA-256 为 5825fc7ebf84ae7a412be049820b4d86d77620f204a041697b0494669b1742c5。沿用已有构建期资产下载与校验机制，随 APK 打包，运行时不联网下载。ONNX IR v10 要求升级现有 ONNX Runtime；VAD、Embedding 等使用同一运行库的功能需要一并回归。

模型来源与授权：[RapidOCR 模型清单](https://github.com/RapidAI/RapidOCR/blob/v3.9.2/python/rapidocr/default_models.yaml)、[PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)，Apache-2.0。

## 本地样本结果与限制

对用户提供的原话截图在当前工作环境运行 PP-OCRv5 移动模型，完整检测流程纠正了多处形近字，但仍把一处“字”识别为“宇”。单独按正文行裁切后，“你一直”“问”“醒来”“转成字”“回来”及重复人名等目标片段读取正确。单行实验每行约 0.3–0.4 秒，是当前 CPU 环境时间，不代表手机速度。

这只是该样本的模型实验，不是 Android 端到端验证。Android 保留 ML Kit 定位，裁切框可能与本地实验不同，实际字符错误率、行遗漏、冷启动和总耗时仍需手机验证。用户截图与私人聊天原文不提交到仓库，不宣称零错字。

## 验证

新增 CTC 连续重复汉字、空白符、中英空格、批次偏移、损坏输出和文字行顺序回归用例。连同已有尺寸用例，在本地 JVM 运行共 12 项测试，全部通过。模型输出词表尺寸必须与打包模型的词表一致；错误时明确记录失败，不把旧模型转写混入新结果。

本地可用 `tools/ocr/evaluate_lines.py --model MODEL --image IMAGE --cases CASES_JSON` 复现逐行裁切、宽度、BGR 归一化与 CTC 解码对照。样本文件保留在仓库外，工具只输出数量、字符编辑距离与耗时；该统计只覆盖提供的行，不是全屏准确率。

使用与 Android 一致的逐行宽度和归一化流程，5 个重点行、88 个参考字符的本地对照全部一致，字符编辑距离为 0，本次推理约 1.02 秒。曾尝试的双行批处理得到 1 个字符错误，已移除；不能把数学等价的归一化和尺寸取整随意替换成另一种实现。该结果不覆盖 Android Bitmap 插值差异、ML Kit 裁切框和手机耗时。
