# [DONE] 固定提示与本轮状态的缓存边界

## 原状与目标

实时状态、软件观察、待办和本轮匹配的角色资料混入 SYSTEM；Claude 发送层又把所有 SYSTEM 合成单块，导致动态值变化时连带改变历史前缀。本次仅调整请求布局，保留状态计算、来源归属、权限规则和模型配置。

## 实施范围

- 固定规则与实时资料使用 RuntimeContextSections 分开生成，固定规则仍在 SYSTEM。
- 世界书保留原匹配条件与优先顺序，由固定规则明确要求应用本轮匹配的角色设定和表达要求。
- ConversationService 每次新请求只生成一次状态，估算继续使用 recordSnapshot=false。
- CurrentRequestContext 先把实时资料放在内部 metadata，待当前用户输入去重、输入变换和提示钩子结束后，再投影为本轮宿主附件。真实 ChatMessage 不变。
- 工具续轮使用相同执行上下文，保留本轮状态；新请求按 metadata 清理先前投影，不按用户正文标签删除内容。
- Claude 保留多个独立 SYSTEM 内容块，沿用工具、系统和末消息三个缓存断点。TTL、供应商、API 地址不变。

## 验证与边界

回归用例覆盖固定前缀、当前用户不重复、旧状态清理、工具续轮、空输入宿主唤醒、角色资料匹配及 Claude 的三处断点和 TTL。实际执行结果见对应提交的检查记录。

缓存收益取决于中转平台、请求间隔和输入内容，需要对比真实 usage 和实扣费用；源码调整不承诺固定命中率。缓存读取仍计入输入上下文。
