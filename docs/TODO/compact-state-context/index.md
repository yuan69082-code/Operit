# 每轮状态上下文去重

仅整理请求表示，不改状态演化、数据或候选评分。状态请求副本省略 triggers、maxDelta、halfLifeHours；当前值、持续性、影响规则、权限、变化和候选原因完整保留。完整定义继续通过内部状态工具读取。

开启内部状态时，念头只在其 JSON 中发送一次，并保留操作说明。外部三项待办提醒仅省略内部32项候选已覆盖的ID，不在候选内的提醒继续发送。关闭内部状态时维持独立提醒。

真实发送记录状态JSON整理前后字符数与条目数，不记录私密正文，也不将字符数冒充token。该统计不包含全部提示词、媒体或服务商封装。

新增测试验证请求投影保留状态意义、评分、变化和完整念头，且不修改原始定义。Android编译及JVM测试由PR流水线验证。

## 宿主说明

聊天和自主活动共用一份轮末报告说明。每轮发送来源与权限规则、常用回报入口、便签进度模板、候选跨轮读取及采用条件，以及真实操作回执和活动续接方式。完整版通过 `companion_internal_state get section=contract` 按主题读取。旧时间规则的完整字段由 `legacy` 返回，已承接基础驱力的说明由 `foundation` 返回。

比较占用时使用同一份状态和输入，按请求分项的文本估算公式计算宿主说明前后的差值。以生产入口的回归验证两类请求保留必要说明，以及工具仍可返回完整契约。

事件回报在每轮说明中明确展示 `"episodes":[{"op":"appraise"}]` 的数组骨架，并列出条目字段。恢复事件与候选来源前先使用共享结构校验。误把操作名当成嵌套字段时，错误指出 `episodes` 的类型和正确格式，下一轮也能收到这条说明。

已收到完整回报并能定位可修正字段时，本轮使用同一个模型请求补丁。只传待修正内容和相关规则，补丁通过原帧与原事务提交，正文和已执行工具沿用原结果。纠错总计最多三次并受九十秒限制，耗尽时记录失败。找不到事件分类时提供基础目录和当前个人目录。模型可选已有合适分类，也可在新事件上附经过验证的个人分类定义。同一事务保存新分类和事件，采用已有的分类索引、时间投影与联合机制。分类只能来自现有大类，必须给出涨落规则，稳定人格等原候选边界继续有效。
