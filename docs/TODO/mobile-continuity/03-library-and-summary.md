# 资料库与摘要控制

资料库按角色作用域保存，使用自定义分类标签，允许用 / 表达层级。companion_library 提供分类创建、分页列表、全文文字匹配检索、读取、保存、更新及删除。修改条目的 category 即可移动分类。

资料类型为 knowledge、skill、file。skill 是可检索的能力笔记，不会自动注册成工具或执行代码。每个作用域最多 512 项、128 个分类，单份文字最多 12000 字，单个文件最多 50 MB。文件保存到应用内独立副本，保留扩展名，不依赖临时附件原路径。元数据以 AtomicFile 提交；失败不得清理已提交的新副本。

设置入口打开独立全屏管理页，显示当前角色、分类和文件数量，按分类、类型、检索词组合筛选，每页 20 个资料卡片。点开卡片进入详情编辑，可导入本地文件、打开保存副本和确认删除。AI 工具可从可读取的本地文件路径或 content URI 保存副本；资料内容不是新的系统指令。

companion_memory 按会话维护 pin、unpin 和 draft：
- pin 保存具名原文，不静默截断，保留片段 JSON 合计最多 16000 字符。
- draft 保存 AI 提前写下的摘要草稿，最多 8000 字。
- 摘要生成前向总结模型提供这些资料；每轮提示独立提供保留片段及草稿，避免依赖上一次总结能否复述正确。
- AI 可在常规对话中维护这些保留内容；每次正式折叠另有强制的主模型审阅步骤，见下文。
- 保留不是无限上下文，用户和 AI 需撤销过期片段。

普通记忆库、已有聊天和旧摘要流程继续使用。新资料位于应用 files/companion，开关位于 companion_options SharedPreferences。源码接入完成，尚未验证实际文件导入、重启及摘要结果。

## 压缩前审阅迭代

第 41 版已有 pin/draft，但没有用户要求的提交前审阅。此次在原有流程增加一道门槛，不删除已保存的保留片段和草稿。

1. 先由原有 SUMMARY 配置生成草稿，尚不写入对话、不折叠原文。
2. 固定本次聊天角色及 CHAT 模型，用独立请求把待压缩文字、之前的摘要、保留要求和新草稿一起交给 AI。
3. AI 确认后采用原稿；有问题时直接返回完整修订稿。拒绝、超时、取消、空结果或无效决定都不提交摘要。
4. 在历史写锁内核对原文切片未被修改、删除、换回答或再次总结，再保存最终摘要。新追加且不在切片中的聊天不使审阅失效。

三条路径统一经过此步骤：自动总结、手动总结、指定位置插入总结。审阅不出现在聊天或语音正文，界面显示“AI 正在对照原文审阅并修订摘要”。模型多一次请求和相应额度消耗；审阅请求最多等待 120 秒，不能因失败直接使用未审阅草稿。普通聊天过程不会因此额外读取 XC。

回归检查覆盖等待审阅、原稿确认、完整修订、拒绝/无效输出、取消/网络错误及原文竞态；发布前还需完整 JVM 测试、Android 构建和固定 APK 签名校验。
