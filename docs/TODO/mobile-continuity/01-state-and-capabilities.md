# 状态延续与能力感知

原来仅有角色提示和头像情绪。CompanionStore 保存角色的 XC 连接绑定及同步回执，情绪本体由 XC 管理。角色卡 ID 作为绑定作用域；未绑定角色卡的会话使用 chatId。与聊天模型及提供商无关。

自动接续 XC 情绪默认关闭。用户在设置 → 状态延续、主动联系与资料库 → XC 情绪，选择已配置并启用的远程 MCP 连接，绑定当前角色。复用 MCP 原有的地址、Bearer Token 和 headers，不在源码写用户服务地址或口令。绑定记录固定端点，原 MCP 地址改变后必须重新绑定。

XC 以一个部署实例管理一套状态；session_id 仅隔离窗口短态，不隔离角色的全局情绪。不同角色若需独立情绪，应绑定各自实例；界面明确说明共享同一实例的含义。检查沿用角色 MCP 工具权限，绑定不会绕过角色限制。

接口依据 [用户 XC 仓库](https://github.com/yuan69082-code/xinchao-nian) 的 a38a0a3241b0d3928d4a452ea1a38cf7efa14cd3。正式聊天请求调用 xinchao_context(mode=turn,max_tokens=2200)，传入由角色及会话派生的稳定 session_id，读取 structuredContent.additionalContext 和 dynamic_state。Token 预估只用已收快照，不请求服务端。20 秒超时或无效返回明确记录未同步，本轮不以旧情绪冒充新状态。

companion_state 提供 get 与 event。event 转发真实 exchange、可选 tone 和稳定 event_id 给 xinchao_event，由 XC 判定互动并更新状态，不开放客户端任意改写数值。重试必须复用同一 event_id；不与原生 xinchao_event 重复上报同一互动。关闭开关后自动注入与这个转发工具停止；原有 MCP 工具仍由其原设置管理，便于引擎接管。

XC 的上下文读取会记录交付并签收自身信号，即使 mode=inspect 也不是无副作用预览。情绪可视化页只展示最近一次对话同步得到的情绪坐标、驱力和近期标签变化，标明同步时间与失败状态，不读取或展示黑匣子内容。连接检查只做初始化和 tools/list，不领取上下文。用户以后若要即时的独立仪表盘刷新，需要接入 XC 的独立只读 Dashboard 授权，而不是冒用上下文交付接口。

能力感知有独立开关，默认关闭。开启后 CompanionContext 提供麦克风授权、通知开关、软件版本、Android 版本、功能开关、模型配置标签、直接媒体能力、后端识别能力和允许的工具来源。请求与上次快照不同会明确说明。Token 窗口预估不更新快照，以免预估过程提前消耗变化通知。关闭后不额外注入快照，companion_capabilities 也停止返回状态；既有工具声明和调用不受影响。

能力快照不能代表调用成功或 MCP 服务在线。心率数据源明确为未接入。软件上下文用 operit_state 标记包围；通话公开文本过滤器会移除完整标记块及跨句块正文。
