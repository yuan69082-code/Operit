# 无新用户消息时整理后台经历

后台回合使用临时请求运行。主动联系和状态唤醒原本会把模型自己写的 companion_note 留作隐藏聊天记录，但自主探索和提交任务跳过这一步；正式压缩又仅在聊天等前台路径触发，且切片要求较早部分包含可见 AI 回复。用户长时间不发消息时，仅有隐藏经历的历史无法独立整理。

本次延续既有经历记录方式，保留模型自己写下的想法、选择和理由，不新增经历归属标题或另一个叙述模型。探索和提交事项也保存既有同款记录；已保存的学习成果、工具结果、资料、私人待办及记忆继续沿用原存储方式。主动联系的情绪事件和未了事项更新仍限定原来的唤醒类型，避免探索改写主动联系账本。

后台经历写入后，在服务自己的任务中重算已保存聊天的上下文，避免把临时学习材料的请求大小直接当成聊天占用。达到该助手现有压缩设置时调用原来的摘要、主模型审阅和窗口段落流程，不要求新的用户消息。记录不足以安全切分时不启动模型，失败后沿用五分钟重试间隔。

切片允许仅有隐藏后台经历的较早部分进入摘要，最近两轮保持原文，未得到回复的普通用户消息单独存在时仍不能压缩。原有整轮工具链等待、提交前原文核验和原记录持久化继续生效。

已添加无可见回复的多轮经历、继承既有摘要、保留最近选择、前台用户消息保护和主动消息配对的回归用例。遵守 AGENTS.md，未在本地执行编译或测试，提交后由现有 CI 验证。
