# 内部状态历史读写修复

## 原状与范围

接续 PR #50 的两次提交，不替换内部状态规则、不接入连续性引擎。2026-11-08 导出日志保留了 JSON 解析路径的 OutOfMemoryError，以及主线程在 CompanionStore.update 序列化内部状态时的系统 ANR。先前候选增加第二个 companion object，Android 构建与 JVM 检查均在 kapt 阶段失败；该非法声明已移除，实际编译结果仍以新 CI 为准。

先前候选必须完整解析旧文件后才能裁剪，且先写回裁剪结果、后追加归档；首次读取仍有内存风险，中断可能丢历史。共享可变 JSON 缓存还会让返回值与以后修改互相影响，并常驻保留多个助手的数据。

## 本次修改

- 逐条读取旧 events、experiences、semantic_reports，分别保留最近 3000、600、300 条，同时限制各历史字段的累计文本大小为约 2 Mi 字符。单条记录不截断，至少保留最新一条。
- 溢出记录保存到 companion/internal-state-history.sqlite，按助手隔离，内容摘要用于重复迁移去重。事务提交成功后才原子替换当前 JSON；中断后旧 JSON 可重新迁移，归档失败不裁掉原文件。
- 所有内部状态写入入口统一裁剪，涵盖消息、工具、报告、用户编辑及时间推进。输出逐项写入文件，避免同时生成整份 JSON 字符串和 UTF-8 字节数组。
- 移除共享可变树缓存；日常读取处理近期历史。当前值、定义、版本记录、私密属性、规则与来源字段保留。版本记录仍用于历史隐私判断，不在本次随意截断。
- 已归档事件仍按 ID 去重。报告回执从归档恢复并沿用原摘要核对；新报告若早于已归档变更范围，明确拒绝过期冲突，不能绕过原冲突检查。按需恢复证据，原 get offset 分页可继续读取归档事件。
- 归档联系时间继续参与时间规则计算，保留各窗口在最早未结算时间之前的最后一次联系及之后的联系边界，不把归档误判成未联系。
- 消息、配置与工具记录在 IO 上执行。工具记录等待完成后再继续下一轮，不使用无界后台任务队列，取消信号继续传播。

## 验证与限制

已做源码调用点检查和 git diff --check。新增 JVM 用例覆盖旧文件迁移、近期记录体积限制、归档失败不裁剪、JSON 数值与字符保持、归档联系后的时间演化与窗口隔离。遵循仓库默认不主动运行编译/测试命令的约定，本地未执行这些测试；提交后的现有 CI 负责编译与回归，结果未提前认定通过。

设备升级后的真实大文件迁移、SQLite 磁盘写入失败/进程终止及长时间手机内存表现仍需验证。本修复限制的是三类历史的日常驻留规模，不宣称整个应用内存有硬上限：当前实例、定义版本、尚未结算的联系边界以及单条异常大的记录仍可能增加成本。归档占用磁盘会随历史增长，不自动删除经历；状态页面保留近期时间线，工具 get 可翻到归档事件，未新增归档页面。

本轮代码修复完成并准备提交；构建通过、合并、发布是独立状态，不以本文替代 CI 或设备验证。
