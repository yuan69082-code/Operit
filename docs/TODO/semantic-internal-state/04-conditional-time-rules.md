# 条件时间规则与可修订定义

## 原状与意图

已有规则以半衰期和每小时漂移表达时间变化，用户难以直接理解适用条件。模型需要能分别定义某个条件下每几分钟增加或减少多少，并在真实经历后自主报告当前体验。

## 约定

- 新状态必须给出驱力、情感、情绪、心理之一，以及完整的增加、减少、最低时间值配置。
- 条件选项只有任何、未联系、自定义。数字建议值为 0 至 30，允许自定义有限数值，不设置 30 的上限；间隔为零或负数暂停该方向，变化量为零不改变数值。
- 联系条件由真实用户消息和模型明确给出的联系窗口判断；自定义原因保留自由文本，由模型在同次报告中标记条件成立或结束。
- 定义了新时间规则后只执行这套规则；未定义的存量状态继续原规则，并清楚显示尚待补齐。
- 自定义条件切换先结算旧条件经过的时间，随后影响未来；定义修订不追溯重算旧历史。
- 模型可通过同一最终报告修改名称、简介、分类、时间规则。稳定 ID、现有体验与历史仍归属同一状态。
- 事件体验更新独立于被动时间最低值，依然受状态总范围和已有来源、身份、事务校验限制。

## 实现范围

`InternalStateEngine`、条件时间计算模块、`InternalStateReports`、`InternalStateStore`、`InternalStateSelection`、`CompanionTools`，以及对应纯测试源码和协议文档。

## 验证计划

核对联系窗口分段、自定义条件切换、不同轮询频率、最低值、旧规则兼容、同轮修订与事件回报原子性、历史隐私。用户已明确要求合并、构建和上传发布；执行必要纯测试和现有 Android 构建检查后记录结果。

条件规则、同次修订、真实消息联系时间及逐方向隐私已完成。本机 122 项相关纯 Kotlin 测试通过，其中包含 14 项条件时间专门回归。完整 Android 和设备表现由发布工作流及安装使用继续验证。
