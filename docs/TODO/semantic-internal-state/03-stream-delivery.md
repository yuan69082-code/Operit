# 流式接入和验证

原始响应流会同时进入回复缓冲、界面、朗读和聊天持久化，因此必须在这些公开通道之前提取结构化状态段。

解析组件跨分片保存状态，识别完整报告并只转发公开内容。思考与代码引用中的标签不得误作状态提交。解析器与供应商的保存点和回滚一起恢复，错误仅暴露错误码，不记录私密原文。

每次成功业务轮结束后提交待保存报告，输入快照保持不变。状态不会触发第二次模型请求；已有工具调用的续轮继续使用同一业务上下文。取消、失败和不完整报告不提交。

原生聊天、工具续轮与接管生成的插件需要明确的接入边界。静默唤醒和群聊的公开发布决定发生在状态分流之后；写回身份来自宿主绑定的助手，而非模型自报身份或 API 消息角色。

必要验证包括分片边界、截断、重复、引用伪标签、回滚、防重、版本冲突、未注入维度更新、新定义与初次体验原子性、私密过滤、预览无副作用以及输入顺序。
