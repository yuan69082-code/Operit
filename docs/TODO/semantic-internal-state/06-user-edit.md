# 用户编辑内部状态

## 背景与目标

已发布的状态详情只能查看，数值、原因、类别和条件规则由模型维护。用户现要求自己也能直接修改，尤其需要调整“多久没有新消息才算未联系”的等待时间。

沿用原状态详情增加编辑入口，不增加新的状态库或模型调用。可编辑当前值、修改原因、驱力／情感／情绪／心理分类，以及增加、减少的条件和原因、间隔、变化量、时间下降下限、未联系等待时间。

## 实现范围

- 界面只提交真正改动的值和定义字段；存量未定义规则保持原样，用户明确选择定义时才要求完整配置
- `InternalStateStore.updateFromUser` 使用原存储事务，原子保存数值、原因、定义版本和变化事件
- 当前值与原因针对选中实例，分类和规则属于该助手的状态定义；稳定 ID 和历史保留
- 规则切换先结算旧规则，暂停自动演化时不补算暂停时间；保存后立即刷新详情与时间线
- 人工修改采用 `user_edit` 来源，不伪装成模型报告，不向模型工具提供人工写入入口
- 保存校验定义版本及语义版本，用户修改推进语义版本，阻止已在途的旧模型报告覆盖新值
- 已发布的 `frame_id` 历史继续可读，人工记录用真实 `event_id` 与时间线和选择器关联
