# 连续内部状态与同轮回报

## 背景

现有内部状态允许助手自建维度，并按事件和经过时间计算数值。请求会带入全部活跃维度；文本事件仍可用字符串匹配触发变化。模型可以修订定义，但不能在一次正常生成里报告本轮体验。

本次迭代保留按助手保存的数据、现有数值与时间参数，增加部分状态投影和结构化主观回报。continuity-engine 仅作为只读参考，不修改该仓库，也不为已经由外部引擎接管的主体建立第二份权威状态。

## 约定行为

- 固定说明、历史聊天、本轮状态资料、当前消息或唤醒事件按此顺序组成请求。
- 普通消息、主动唤醒、手机与软件感知、自主探索使用同一状态协议。是否公开发言独立决定。
- 同次输出可先提供状态段，再输出公开内容。状态提交供后续轮次选择使用，不要求本轮重新读回或下一轮必定选中。
- 模型可以更新未被本轮展示的已有维度，也可以创建新维度；未报告的数据保留。
- 新维度区分驱力、情感、情绪，并明确其含义、范围、基准、时间参数。存量参数保持，不预置具体情绪或统一速度。
- 语义状态是主体对经历的理解，来源与对象可追溯；自述不能充当工具执行成功或用户事实的证明。
- 只有完整、有效、成功结束的报告才进入原子提交。重试、回滚和取消不能导致部分写入或重复增长。
- 状态段不进入公开气泡、朗读、通知或普通聊天正文。不会因此固定增加一次模型请求。
