# 失效会话的待发送消息停止自动重试

用户反馈首页反复出现“会话不存在”。代码路径为 SubjectLife.next 选择 queued 输入，CompanionRuntime 调用正常发送入口，MessageCoordinationDelegate 在解析所属会话时失败并直接返回；收件记录尚未被 claim，仍为 queued，下一次生活调度再次发送并再次弹窗。截图与这条路径相符；尚无本次设备堆栈来排除其他来源。

修复在原发送前错误分支持久标记 queued 输入为 failed，保存失败原因并通知原完成回调。仅变更同一助手、同一 source_chat 的待发送项；已认领的发送不会被迟到错误重置。原文、原始会话、时间戳及附件不变，不自动换窗口或重跑操作。首页沿原失败输入展示原因，原有明确重试入口保持。

新增缺失会话失败后重开读取、退出自动队列、正常新输入不受阻、已认领输入不被重置的用例。用户此前授权验证后构建并发布；本次沿用原流水线，结果以最终候选为准。没有更改主体运行、睡眠、自由时间或全局重试策略。
