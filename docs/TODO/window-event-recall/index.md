# 短事件目录和完整原文回查

原事件内容和感受过长，跨窗口目录被自动重复携带；history 截断长消息并隐藏工具正文，缺少续读入口。更新检查还把 GitHub 返回顺序当成版本顺序。

1. 收短新事件，统一状态。数据库摘要保留累积事件；发送聊天模型时只带最近十二件和未结束事件。完整感受和旧摘要仍保存在原记录。
2. 增加同一助手所有私聊的事件检索，按关键词、时间和状态分页返回。复用数据库中最新摘要作为窗口存档，不建立第二套同步文件。
3. history 支持事件终点和明确分页状态；history_message 按字符续读正文、工具或附件原始标签。私聊读取归属与群聊隐私边界保持不变。
4. 个人更新读取候选发布清单，以实际 Android versionCode 选最新版本，不依赖 GitHub 列表顺序。

本次为现有接口增量迭代，原 history 参数保持可用。依仓库要求不主动执行本地编译和测试；新增回归测试交既有 CI。设备覆盖安装仍需验证。

## 已实现接口

- `group_chat action=windows query=标题 offset=0`：同一助手的私聊窗口清单，包括未生成摘要的窗口
- `group_chat action=events query=关键词 chat_id=可选 from=可选 end=可选 status=悬着或已结束 offset=0`：每页十件，返回窗口 ID、起止时间戳及保存摘要的位置，继续传 `next_offset`
- `group_chat action=history chat_id=窗口 after=事件from end=事件to`：每页最多二十条，返回 `has_more` 和正序续读游标；`range_list_complete` 仅表示消息清单已经列完，长正文需展开
- `group_chat action=history_message chat_id=窗口 message_at=消息at part=body offset=0`：每页最多六千字符，继续传 `next_offset`，直到 `complete=true`。自己的私聊可选 `raw`、`tools`、`attachments`，群聊始终只开放公开正文
- `group_chat action=feelings chat_id=窗口 from=事件from end=事件to offset=0`：分页读取自己保存的完整感受，覆盖最后一条回复生成过程的记录

新事件要求一两句精华，旧长段落仅取有标记的节选，不让另一个模型重新编造感受。存档保留所有事件精华，发给聊天模型时只附最近十二件及仍悬着的事件，其他事件按需检索。事件续接使用原起点作为稳定索引，更新一个事件不吞掉其他悬着事件。旧摘要和原聊天不批量改写。

感受记录取消原来的三百字符截断和二百条滚动删除，原话继续保存；旧版本已经删除的记录无法凭索引恢复。附件标签可完整读取，但附件文件本体必须仍存在，并由对应文件或媒体工具打开。当前读取的是数据库中所选消息版本。

## 覆盖更新核对

第10、11、12次双端预览均已构建成功并发布 APK，第12版最终签名检查与版本检查通过。单独 Android Build 被有意跳过，实际 Android 构建位于双端预览的复用工作流。GitHub 发布列表实测将第9版排在第12版之前，旧检查取第一项导致错判；现按候选清单中的实际 Android versionCode 选择最新包。

更新保持现有包名、签名及版本码规则。带旧检查逻辑的安装包需要手动覆盖安装一次修正版，此后使用应用内更新。未修改系统安装确认流程。

更新历史页面同时修正：个人 Debug 版显示配套预览发布，按发布时间排序，不再把第10～12版等实际安装包因 prerelease 标记全部隐藏。

已补回归用例：乱序发布选择、长消息跨页重建与表情边界、完整事件存档与输入投影分离、重复投影稳定、多个未决事件分别续接、回查结果不被摘要投影截短。提交后由既有流水线执行，构建和设备结果另行核实。
