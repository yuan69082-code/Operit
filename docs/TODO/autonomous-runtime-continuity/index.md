# 自主运行与活动接续

用户要求基于最新更新完成自主运行、内部真实时间、开关、异常恢复，并保留已有通顺闭环，验证后发布。

已存在：CompanionRuntime统一调度8类来源，SubjectLife活动检查点与休息暂存，参与式梦境，PrivateTime自由时间，SubjectConcerns持续关注，统一材料预算和状态报告采用。

本次补齐统一运行控制、可选空闲判断、真实互动时钟、持久异常暂停、原生与网页入口、AI使用说明。复用原活动/工具回执/内部报告，不另造心理状态或第二个模型调度器。

检查重点：总开关在领取工作前生效，设置变化取消运行；空闲机会排在既有工作后，休息和外部引擎绑定不启动空闲轮；恢复不重放未知工具；各来源公平轮转；活动接续ID版本不能卡死；时间不因压缩或跨窗丢失。

步骤：
1. 统一调度控制与持久恢复，增加可选空闲机会和AI说明。
2. 原生、网页控制入口与时间查询，验证数据归属和状态闭环。
3. 回归测试、现有全套CI、Android和Windows构建，使用已有验证发布流程。

## 已实施

总开关和手动/定时暂停在领取后台工作之前检查，并取消本机拥有的后台轮次；群聊自主唤醒也遵守总开关，普通群聊不取消。空闲机会默认关闭，按助手设置间隔和每日上限，在已有工作之后使用同一运行入口。外部引擎关联、休息、前台聊天或通话不会启动空闲判断。

运行中断或模型执行失败持久标为异常暂停，恢复仅放开后续判断；未知外部操作保持原活动回执，不自动重放。本次没有叠加模型请求重试层，以免与提供商已有重试重复消费。已完成步骤、梦境与原状态采用仍使用原机制。

时钟按助手保存用户接收、回复、主动联系和已记录往返；数据库只查询时间聚合以兼容旧安装，不扫描整段对话。压缩后保留时钟。空值表示未知，时间倒退时不给负间隔。

AI通过简短系统说明和companion_life runtime_status/runtime_wait了解用途、状态和规则；详细时间按需查询，不在每轮追加完整快照挤占原材料预算。人格、情绪、关系等通过原材料选择、活动回执、feedback和operit_state_report参与，不引入自动心理增减。原生助手空间和网页私域提供控制。

修复来源轮转模数不一致，以及结束检查点覆盖模型已明确选择继续/结束的问题。候选检查覆盖Android单元测试、网页类型检查和桌面测试，产物沿现有同源发布流程。

验证中的补充：普通往返完成时记录交流时钟；完成已有活动后顺延默认空闲机会，避免旧空闲计时器立刻重复唤醒，但保留模型本轮明确选择的时间。结束时保留续接选择及最终工具用量。

第250次候选检查：Windows测试、类型检查和构建通过；Android编译通过，2280项测试发现两处回归。完整时钟占用了普通聊天既有事件的材料配额，改为通过runtime_status按需读取，保留原预算与事件选择规则。暂停测试先完成存储初次采用，再比较操作前后完整状态，避免将归档游标的读取投影误认作心理变化。独立Android测试任务另遇NDK下载损坏，下次候选重新执行安装和全套验证。
