# 主动活动工具额度触发应用崩溃

用户的异常堆栈和错误页指向 CompanionRuntime.beforeTool。原实现超过十二次就通过 check 抛 IllegalStateException，调用点在 ToolExecutionManager 的工具执行错误处理外，异常可进入应用全局错误页。这是预期额度状态，不应成为不可恢复错误。

1. 把额度检查改成返回普通拒绝原因，工具执行器将未执行的调用补为失败结果并维持原调用顺序
2. 保留每轮十二次普通调用上限，不执行超额工具，不增加自动重试；每轮仍重置计数
3. 保留 companion_schedule 收尾入口，同时允许探索自身的 schedule/pause 通过预算检查，后续原有权限、开关、间隔和每日限额检查仍执行
4. 探索设置改变导致的预期撤销也返回工具拒绝，不在同一位置抛未捕获异常
5. 增加额度耗尽、重复拒绝、调度收尾和下一轮重置的回归用例，沿用既有 CI 构建发布

本次只改工具入场判断，不关闭后台学习，不删除经历，也不增加后台唤醒次数。本地未主动运行编译或测试，构建、测试、签名及设备验证分别报告。
