# 拒接、取消与挂断通知

## 原状与修改

已接通后的用户挂断会发起普通文字消息，但拒接来电和接通前取消只写历史，不触发 AI。用户需要这三种操作都实际发送给通话所属助手。

- 将用户通话结果统一放到应用生命周期内的 `VoiceCallEvents.sendUserOutcome`，通过正常消息流程落库并触发文字回复。应用内拒接、通知栏拒接、用户取消和挂断共用此入口，不再同时另写一份结果历史。
- 使用明确的三种结果：挂断、拒接、接通前取消。模型收到对应说明，拒接与取消不标成接通过，也不把客户端操作当成用户说出的原话。AI 自己拒接、撤回来电以及无人接听超时仍记录实际发起方，不伪装用户动作触发额外回复。
- 消息指定原会话和助手，不读取当前窗口作为接收人；私聊重新检查所属助手。来电用请求编号核对，消费待接状态后再发送，重复按钮、旧通知和超时回调不会为同一通来电重复发消息。已接通/取消仍由控制器既有终结标记保证一次。
- 来电可能发生在 AI 工具执行期间：通知等待原会话空闲后发送，最长等待3分钟，只取消本软件拥有的后台主动活动，不打断无关的普通聊天请求。资源释放不等待这次文字回复，关掉通话界面不会取消发送任务。
- 通话结果使用自己的文字输入，不读取或清除草稿、附件与引用。等待超时、原会话删除或归属改变会明确提示失败；模型/网络错误由正常消息流程显示，不自动重发或重拨。

## 待整批验证

本步已做静态差异及调用点检查，尚未运行测试、构建或真机验证。整批验证时覆盖：

- 用户在应用内及通知栏拒接来电：原私聊各出现一条“拒接来电，未接通”，并触发该助手的文字回复。
- 拨号等待 AI 决定或 AI 暂缓接听期间取消：发一条“已取消通话，未接通”，不误报挂断已接通电话。
- 正常接通后挂断：原有“通话结束”文字通知与回复继续工作，录音和摄像头先停止。
- 双击拒接/取消、旧通知、接听/超时临界操作：不重复结果，不误拒下一通来电；AI 自己拒接/取消、自动超时不新增用户拒接消息。
- 发起来电后切换助手/会话或退到后台再拒接：仍送原会话；已输入文字、附件、引用保持原样。
- 原会话正在回复时拒接、后台主动来电时拒接、取消时正在工具调用：释放对应旧请求后发送，不被忙碌检查丢弃，不把新文字回复当旧通话取消。
- 原会话删除、归属改变、等待超时、模型未配置/断网：可见失败信息，不声称发送成功。
