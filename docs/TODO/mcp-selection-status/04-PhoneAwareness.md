# 手机感知与隐藏事件

## 原状与本次范围

旧主动联系只接收解锁广播，事件仍要等既定唤醒计划到期；没有应用访问日志或单独授权的后台内容查询。用户需要亮灭屏、锁定/解锁、应用进出与停留时间，并让助手自行选择安静、工具干预或发消息。

采用软件核心前台服务采集，加 `phone_awareness` 查询工具。不是安装一个 Android 系统特权服务，也不让一个仅在被调用时运行的包承担常驻监听。

## 采集与授权

- `PhoneAwarenessRuntime` 由既有 `AIForegroundService` 管理，功能关闭不采集。使用情况访问已存在于清单；可经用户点击使用已授权 Shizuku 开通，或打开 Android 权限页。
- 亮灭屏与解锁来自系统广播，锁定状态同时读取 Keyguard；应用前台进出通过 UsageEvents 约每2秒查询。内部 Activity 快速转换合并为同一次访问，离开后记录已观察的时长。灭屏不等于关机，前台不代表用户注意力。多窗口仅表示最近前台活动，不能精确推断每个并行窗口的注视时间。
- 新服务从启动时开始观察，不假造之前已经打开的应用的进入时间；系统停止服务、权限不足、查询中断时存在覆盖缺口。退出或强行停止后不能保证持续感知。
- “记录手机状态”和“事件唤醒”独立开关，默认关闭。用户选定一个助手及其私聊作为观察目标；不会广播给所有助手。指定目标时启用该助手的查询工具，之后仍可独立取消能力选择。
- 本机保留最近7天、最多1500条元数据事件；提供应用排除、内容授权和清除入口。被排除应用的记录与页面缓存删除。查询仅限指定助手自己的私聊，并再次检查会话归属、助手存在和授权；不以主助手身份自动扩大手机内容授权。

## 事件处理

解锁、进入应用产生持久待判断事件；屏幕开关与离开事件只记录。密集事件合并，默认两次判断至少30秒，可设置5–600秒，模型上下文至多带最近10条元数据，其余可分页查阅。

事件不等待定时主动联系，也不消费或修改定时计划。正在聊天、群聊或通话时等待空闲。工具执行期间和结束后5秒内的变化仅记录，避免 UI 工具操作导致循环唤醒；这一窗口内的用户行为也可能只记录而不唤醒。单纯模型生成期间仍保留待处理事件。超过5分钟或设备时间异常的旧事件不再触发干预。

沿用观察助手自己的模型、工具及正常权限，隐藏输入和中间结果不存为聊天气泡；只有最终明确的主动消息写入私聊，重复内容拦截。可安静结束，不强制联系。每次最多12次工具调用、3分钟。用户输入、目标/权限设置变化取消当前事件判断。失败、中断不自动重试副作用。事件有待判断、判断中、已判断、取消、过时、失败、中断状态，具体工具及决定写入既有唤醒日志。

## 不打开应用的内容边界

`app_content` 返回用户逐应用授权后可用的两种明确来源：

- 当前通知：要求通知监听授权和实际连接，标明发布时间；不会冒充完整聊天历史。
- 已见页面：应用此前实际可见、手机解锁时由无障碍读取文字，最多每15秒采集一次，排除 password 节点，限制长度。缓存保留观察时间并标记非实时；校验窗口包名，防止快速切换写错来源。

查询不会打开目标应用。一般 Shizuku ADB 权限为 shell，不能任意读取 `/data/user/0/<其他应用>`。应用未开放的完整后台内容仍需单独对接它提供的授权 API、MCP、ContentProvider 或导出；本次没有做通用私有数据库读取。

依据：[Android UsageStatsManager](https://developer.android.com/reference/android/app/usage/UsageStatsManager)、[Shizuku API 权限限制](https://github.com/RikkaApps/Shizuku-API)、[Android 内容提供程序](https://developer.android.com/guide/topics/providers/content-provider-basics)。
