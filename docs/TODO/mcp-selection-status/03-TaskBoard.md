# 私人打算与群共同事项

用户希望参考待办控制台，但不将它限制为人类派发的任务：助手可以记录自己的心愿、私人事件和长期计划，自行批注、提交、继续或暂缓。确实需要用户作出选择时才填写待决定内容。截图仅作为交互参考，没有复用截图所属项目代码或业务数据。

## 数据与界面

`TaskRecords` 提供共同记录规则，`TaskBoard` 仍将私人事项保存在所属助手的 `role:<id>/todos`，群事项保存在对应群会话的 `tasks`。没有将各助手的私人待办合并。保留旧记录内容、紧急程度和长短期含义；旧数据没有作者时明确显示未署名，不猜测归属。

每项有不可变作者、可调整接手人、P0–P3 优先级、长短期、状态、分类、共同计划、当前结论、实际进展、下一步、参考资料、关联事项和可选的待决定内容。批注和操作按执行者 ID 署名，最近 80 条操作记录可展开查看。私人事项完成后仍可沉淀到自己的资料库，或删除；正在处理的条目需等本轮结束后再删除，避免丢失处理中记录。

`TaskBoardPanel` 供私人和群界面共用，包含搜索、状态和接手人筛选、分类、优先级调整、批量归档、编辑交接、批注和处理记录。保存不等于执行，处理结束也不等于事项完成。编辑携带记录版本，防止旧编辑内容覆盖新批注。

## 助手接口与事件

- 私人 `companion_todo`：`list/get/save/comment/submit/delete/distill`
- 群 `group_chat`：`tasks/get_task/save_task/comment_task/submit_task`
- `details` 是记录字段的 JSON 对象，只修改明确提供的字段；原作者不能改写。
- `submit` 指定接手助手及延后分钟数，0 表示等待空闲后尽快处理。私人范围只能交给自己，群范围只能交给现有群成员。
- 列表每页 20 项简表；详情通过 ID 获取，批注历史每页 5 条。普通上下文仅带少量条目索引，事件带有限摘录，避免每轮重复注入完整记录。

提交事件由已有前台服务处理：普通对话、通话及群讨论空闲后，使用接手助手本身的模型与已授权能力执行。服务仍受 Android 运行条件影响，未运行的软件不能自行执行本地事件。

处理状态为等待、处理中、已处理、失败、中断或取消；任务状态独立保存。领取事件与读取最新批注在同一存储锁中进行，重复领取和已取消提交不会重新执行。处理中可安排下一次继续，助手自行安排至少延后一分钟；本轮失败或中断不自动重复执行。进程恢复将未结束的处理标记为中断，保留日志供核对。

暂缓、完成和归档会取消尚未执行的提交、清除后续安排；正在进行的回合仍记录实际结果。群游戏期间日常待办等待游戏结束。私人待办的工具输入和输出不放入其他成员的群公共上下文。
