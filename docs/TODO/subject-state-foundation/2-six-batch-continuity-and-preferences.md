# 六批连续目标与人格、偏好补充

以下保留园园确认的完整六批目标。第 1 批落实主体底座及报告异常隔离。第 2 批实现内在记录、持久候选/采用、偏好与正常选材接线，见 [第 2 批实现与交接](3-batch-two-implementation.md)。第 3 批承接类别内独立事件、主体安排的3—6个重点位置、求生欲特例及人格/关系/偏好的累计经历关联，见 [第 3 批契约](4-category-events.md)。第4批已接入同轮候选中的联合与成员原子变化、实际材料来源和统一预算，当前验收进度及第5批入口见 [第4批交接](6-inner-interactions.md)。第5—6批尚未实施，不能把联合解释当成完整外部执行反馈或梦休息已经完成。

独立缺陷提交打通 [聊天、书房和唤醒的实际结果](5-activity-continuity.md)，复用现有消息与书房存储，不替代内部状态权威。第4批沿用 episodes 候选、experience_link 累计关联、既有 inner propose/adopt 和统一报告版本边界；不得另造人格/偏好副本，或以事件强度自动改写人格、关系和偏好。

## 六批规划（完整目标保留）

| 批次 | 范围与后续接线 |
| --- | --- |
| 1：底座 | CharacterCard.id 归属、现有存储事务、来源、版本、幂等、迁移、正常入口；核对人设注入与覆盖路径。为偏好明确同一主体归属与后续使用位置，不实施偏好机制。 |
| 2：完整内在结构 | 驱力、需要、情绪、情感、人格、自我认识、价值、立场、关系、偏好。已导入人格或人格稳定后，持续保存的人格/自我认识/价值/立场成为主要依据，人设词退为初始参考。区分初始设置、用户提出的变化、主体实际采用的变化，保存采用过程，不能编辑人设后直接宣称主体已经改变。 |
| 3：类别内部事件与特殊规则 | 为各类别建立真实事件与规则，包括偏好的形成、确认、改变、暂停及情境适用；不能把未表态、一次随口回应或迎合行为自动认定为长期喜好。原事件来源、对象与缺失证据保持可辨。 |
| 4：双向作用 | 偏好与驱力、需要、情绪、情感、人格、自我认识、价值、立场、关系相互影响；明确作用与冲突，不用某一高分机械决定一切。 |
| 5：正常思考、选择与真实反馈 | 经主体采用的持续状态进入正常判断与外部行为选择；工具/模型是能力，结果回流后可改变偏好及其他状态。选择不等于执行成功，用户建议不等于已采用。本批仍是业务轮结束后保存报告，不能宣传已实现同轮先改变内心再回答。 |
| 6：时间、休息、梦与连续承接 | 同一主体跨窗、换模型、重启后保持生命周期；长期偏好、短期兴趣、情境性选择按各自已确定规则承接，不擅自以超时清空人格或把未完成事件归为解决。 |

引擎第八、九批专项工作不包含在以上施工范围。本批没有决定未来必须全量 Python 嵌入或全量 Kotlin 重写。

## 人设注入与覆盖路径：第 1 批基线核对

以下“当前”“未来”描述的是第 1 批基线。第 2 批已在 combinePrompts 标明初始配置，并由 CompanionContext / CurrentRequestContext 读入已采用身份、在提示词 hook 之后重申优先级；保留原文中的身份资料、工具契约和运行限制。没有以规则判断观点价值，也不以对话轮数宣布稳定。

1. CharacterCardManager.convertTavernCardToCharacterCard 把导入卡的 description/personality/scenario 合成 characterSetting；示例、system_prompt、post_history_instructions 合成聊天补充文字。这是导入配置，当前没有独立的“主体采用”记录。
2. CharacterCardManager.combinePrompts 组合 characterSetting、聊天或语音 otherContent、附加标签、advancedCustomPrompt。ConversationService.prepareConversationHistory 在未携带 SYSTEM 的请求中，将它交给 SystemPromptConfig.getSystemPromptWithCustomPrompts；代理卡还会经 proxyRolePrompt 进入 SYSTEM。已有 SYSTEM 的工具续轮会沿用该段，不是每个网络分片都重组，但新请求仍可能重新注入初始文本。
3. ConversationService 在正常请求中调用 RoleRules.contextSections；用户配置的 tone 进入 instructions，匹配 worldbook 进入 state。当前世界书规则要求按优先顺序应用角色设定。它们尚未区分主体自发偏好与用户配置，不能把 tone 直接迁移成已形成的喜好。
4. RoleRules.transform 还会变换输入和输出文本；SystemPromptConfig 的自定义模板及 history/system compose hooks 可以改变请求文字。未来只改 CharacterCard 字段不会自动解决这些路径的优先级问题。
5. CharacterCard 编辑/导入以及 assistant_admin set_role 会改变后续提示词来源。本批已经禁止其他助手（包括主助手）代写开启内部状态的主体人格，用户及该主体原有编辑入口保留。没有把这些编辑记成主体心理成长。
6. 当前没有代码把 characterSetting 每轮直接写回 internal-state 数字实例；风险是提示词语义上压过已发展的人格。此优先级仍是明确的后续冲突，本批不提前删除现有身份提示，也不声称已经解决人格采用。

## 偏好归属与接入位置

偏好归属于现有 CharacterCard.id，与模型、窗口、后台任务无关。同一助手跨窗持续承接；另一助手不能从通用写入口代写。情境适用可以包含会话、对象或事件条件，但不建立第二个主体副本。

覆盖语言方式、思维方式、喜好、爱好、喜欢/不喜欢的对象、话题、事件类型，并允许扩展。必须分别表示长期偏好、短期兴趣、情境性选择、迎合他人的行为；保存真实来源、对象、适用情境、变化过程及证据缺失，不能混为一个喜欢分数。

- 第 2 批确定具体结构与采用语义后，复用 SubjectStateBoundary 的归属/版本/来源边界和 CompanionStore 事务。是否新增职责域由真实结构决定，本批不新增空域或空类。
- 提示词优先级在 CharacterCardManager → ConversationService / SystemPromptConfig / RoleRules 的已核对路径统一处理。初始设定不能持续覆盖已采用的人格；用户新建议应作为建议来源进入采用流程。
- 读取/选择复用 CompanionContext、InternalStateSelection 与现有请求帧，不另建平行注入器。人格/偏好采用和双向作用由第 2–4 批实现。
- 第 5 批沿用消息、工具结果和后台事实入口接反馈；继续保留实际作者、接收主体、来源会话、幂等标识。当前工具/事件已接线不代表偏好作用已完成。
- 原本地记忆、MCP 外部记忆、资料库仍是既有能力；不新造记忆或资料库，不用模型名字当人格主键。

## 明确授权的报告异常修复

截图提供 MALFORMED_REPORT_TAG / LATE_REPORT 与崩溃的描述，没有原始模型输出或完整栈，不能断言哪句话被误判。解析器继续拒绝不合法格式/顺序，不把坏报告当成功，不泄露报告正文，也不自动重跑模型或已经执行过的工具。

本批修复两个可由代码确认的边界：已锁存的报告错误不再通过后续 savepoint 从独立事件订阅抛出；消息文本、朗读、通话等子订阅加入可捕获失败的嵌套 coroutineScope，取消并等待兄弟订阅后将失败交还所属回合。测试直接调用生产解析器与收集边界验证两类错误、取消和下一轮可继续。没有用全局吞异常、放宽 JSON 或补造报告来掩盖错误。
