独立缺陷提交，承接第3批分支和未合并 #54 / #53。不是第4批联合演化，也不改界面布局。

## 已确认的断点

生产后台原来先写“已开口”的隐藏记录及联系账本，再保存聊天正文；书房工具仅返回 saved，未返回确切回复身份。普通请求缺少近期书房实际记录投影。书房唤醒中断后仍保留 pending，下一次调度可能再次执行模型和工具。

运行聊天历史已从数据库读取，并非仅用页面旧列表；没有依据将截图中特定13:27重复补答归因为某个缓存。没有真机日志，不能从助手自述证明根因。书房父页面原来已监听 revision，本次给 StudyPanel 自己补监听，保证单独入口也刷新，不声称已复现特定设备刷新故障。

## 实际保存与读取

CompanionRuntime 的公开表达先走 ChatHistoryDelegate.addWakeMessageToChat → ChatHistoryManager.persistWakeMessage，再发布 UI、隐藏活动记录、账本和通知。保存键由助手ID和稳定触发ID确定，使用 messages 的保留负数主键域；同一键只能对应同一目标会话和内容。既有正常消息仍用正数自增主键。共享 ChatMessageTimestampAllocator 防止前台与后台时间标识碰撞。没有新增消息数据库或全局网络锁。

书房 reply/annotate/review 返回真实书目、章节版本、批注线程、作者、reply_id、operation_id、saved_at。相同操作ID的内容冲突会拒绝，不能伪装成功。saved 不表示用户读过。companion_study note 可按书目和 note_id 查原文；activity 获取近期实际事实。

CompanionContext 在同一助手自己的私聊入口读取最近8条实际聊天节选（SQL限制每条1200字符、尊重选中回复分支），以及最近3本书各3条批注和触发状态。群聊和其他助手不注入这些私聊/书房内容，书房工具也要求主体自己的私聊入口。书房回复仍是书房来源，不扮成用户消息。

聊天原文可经 companion_room message，使用 details.message_id/offset 每页2400个Unicode字符读取；SQL直接选取片段，且再次限定所属助手与私聊，不要求拥有主助手管理工具。

旧书没有近期索引时，仅显式提供旧书目索引末尾3本的兼容查询，并标注这不是按活动时间排序；不编造时间或重写旧批注。书房原有整书JSON保留，近期投影流式扫描但只保留末尾3条；内存与模型材料有界，扫描IO仍随单本旧文件长度增长。这不是本批事件历史的SQL有界查询，后续若拆分书房存储须另行迁移，不在这里悄悄重建资料库。

## 触发状态与中断

书房事件用既有事件ID集合构成稳定触发身份，原子 claim 从 pending 进入 processing。重复调度不能重复领取。handled 仅表示本次处理结束，回复成功必须查实际持久回复。取消或上次进程中断转 unknown，不自动重跑模型/工具；失败保留失败状态与现场。新的批注仍有独立触发，可以继续补充已回复线程。

既有人工“重试失败任务”属于用户明确重试；不能当作原任务从未执行，应核对已保存回执。本次未保证外部不可幂等工具的跨服务恰好一次执行；不知道结果时不宣称成功。

## 验证边界

ActivityContinuityEntryPointsTest 通过正式批注保存、StudyTool 回复、后台消息持久入口和 CompanionContext 后续请求组合，覆盖回复回执、重复键、空回后补答、并发领取、并发聊天/批注、跨助手拒绝与新实例读盘。未调用真实模型或真实 Android 调度器；不把助手说“记得了”当作证据。组合测试和构建结果待CI后补齐。
