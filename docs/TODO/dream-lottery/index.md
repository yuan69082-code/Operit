# 梦境抽签、角色分工与真实结果

基线 86f1b3f9aeec4349b3dc249e9b7eaf6cb5ac8c89。只修改 Operit。

用户要求：睡眠安排里可选择单主题、多主题或交给抽签；具体类型随机，增加春梦与冒险。材料方式独立抽取：故事资料为主或当前内部状态为主。类型是起点，允许在经历中变化，不是规定结局或按列表顺序执行的剧情。来源无固定先后，抽样后打乱。所有材料共用既有预算。

复用当前助手模型与持久归档，为每个助手增加可选场景辅助模型配置。辅助只负责环境及行动后果；主体参与仍使用自己的模型。固定分工，不新增裁判或真实工具操作。

修复非空拒答被标为完成、失败内容冒充梦境片段、旧 dream 查询看不到参与过程。保留原始输出和成功片段，显式区分角色、结果和结束原因；恢复沿用已保存抽签与材料，不重新抽取或自动重试模型。不迁移或删除旧梦，不把私密梦境全文自动公开。

验证：纯逻辑抽签/预算/协议测试、实际存储与正常梦境入口集成、重启/恢复/跨助手/错误结果测试、全量 Android JVM、APK 与共享端构建，核对同提交后发布。模拟模型证据与真实模型/手机验证分开报告。

## 实现与使用

`SubjectRestPolicy` 接受 `dream_plan.theme_mode` 和可选的 `theme_count`，不增加一次询问模型的调用；主体在正常睡眠安排中作出单主题/多主题选择，也可交给随机。`DreamDesign` 等概率抽类型与两种取材方式，结果先保存后执行，恢复时沿用已保存结果。主题数组不代表剧情顺序，不要求用完。

`DreamMaterials` 只从本助手私聊最近 16 条、最近一次摘要、固定记忆配置中的少量抽样、现有阅读历史的一页中取片段，不遍历全部历史，不新建记忆系统、不主动连接远程 MCP。之前已经读到聊天中的 MCP 内容可以作为聊天素材。已采用人格的长文片段也能进入状态取样；未采用候选不冒充人格。

资料和状态按 4:1 或 1:4 分配同一材料预算，片段含来源和明确截取标志；后续步骤仍与前两段梦境共用预算。原文保留。默认材料预算仍为 2048 Token，上限 16384；完整请求另核所选模型窗口。已有每次 1–6 组交替及超时、打扰安排保留，没有闲置造梦或失败自动重试。

`DreamSettingsPanel` 位于私域内部状态的休息页。场景配置按助手保存于已有房间配置，选择和清除都不改变主体聊天模型。已选模型失效时明确失败，不能偷偷切换收费渠道。场景和主体分别请求，固定职能，梦中无现实工具。

`ParticipatoryDreams` 接受带角色和结果的 JSON。有效参与才记入 `text`；失败/未参与/格式错误的原始输出存 `raw_response`，不进入醒后梦境片段。自然结束记录真实结束原因与进度，拒答不会标完成。格式验证不能证明任意模型都遵守场景职能，真实模型仍须验证。

`SubjectLife` 原入口支持明确重试，沿用抽签和材料并跳过完成步骤。`get section=dream` 增加参与过程索引，旧静态梦列表保留；过程列表不重复携带全部材料，按 ID 才读取。旧历史不做迁移、不靠关键词回写已经保存的梦。

## 同轮追加：余韵、索引与节奏

用户在首轮 CI 期间补充了梦醒闭环与节奏要求，PR 转为草稿阻止旧候选发布；补充完重新验证后交付。

第一阶段还独立抽整体 short/medium/long，在主体给出的 steps 调用预算内采用约三分之一、三分之二或全部组数，每组另抽 linger/flow/jump。它们不分配主题，也不要求切换主题；抽签持久化并在恢复时沿用，主动结束仍有效。

余韵沿用 `dream_understanding → episodes/inner/foundation/unions → 下一次请求与选择`，没有独立情绪副本。已有联合时间规则可以 hold，或 linear/exponential 向主体给出的强度演化；不因归档、到期或读过一次梦自动归零。梦与现实区分继续生效。集成新增验证正常梦醒报告、实际读取、情绪/探索事件、三天 hold、后续正常请求，以及归档后余韵仍保留。模型判断均为受控模拟。

`DreamShelf` 是现有档案的索引投影，不是另一套记忆。普通请求只选择少量日期、关键词卡片；上下文预算不变，列表不能冒充实际读过全文。`SubjectRecall` 复用现有有界索引进行相关检索；按 ID 取正文和步骤。醒后理解可附 retention=active/archive、retain_until、review_at、keywords；归档或主体自定保留期到期只退出普通轮换，相关回忆仍可查阅。设置 active 且不提供 retain_until 表示重新持续保留；时间0用于清除既有安排。review_at 仅提示复查，不新增闹钟。原有自选经验整理入口明确包含梦的筛查。

采用归档而非删除：完整经历和已形成认识保留在 `companion/internal-state-history.sqlite`，不驻留所有正文，也不每轮发送。磁盘仍随保留的梦增长，不能把归档宣传成释放全部磁盘。流式 requested/partial 与进程 running 只替换持久恢复点，不为每个增长前缀再存一份历史；完成、失败、明确重试等结果继续存版本。旧历史不回删。参与梦的版本查询也补上与正文相同的私域限制。

## 验证记录

本地隔离 JVM：`DreamDesignTest` 6 项、`DreamShelfTest` 2 项、`SubjectRestPolicyTest` 6 项通过。存储集成新增覆盖：场景/主体分别调用、未参与与格式错误保存、原抽签与材料恢复、自然结束、过程查询和列表体积、按助手配置、技术检查点去重和私域历史、余韵与归档后的相关回忆。

全量 Android/Robolectric、安装包和共享端结果以本分支的发布工作流为准。模型回答使用注入的受控模拟响应；不能据此宣称真实模型体验、真实手机后台时序或长期运行已通过。

追加后的第223次工作流执行2227项，2失败、6跳过。归档梦的关键词漏读已定位为 review 位于记录根部，检索误从 content 中取；已修复并加入纯逻辑回归。另一失败为旧多类别缓存测试把梦过程构造成主观报告的 content 形状，已改用真实的根部 index_text，保留原缓存重量和记录完整性断言。本地梦境与共享检索合计17项通过；最终交付须等待后续同提交全量验证。
