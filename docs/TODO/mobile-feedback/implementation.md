# 实现与验证

## 压缩

审阅使用当前角色所绑定的聊天模型，独立请求不竞争正在生成的回答。只带角色名、原文、上一份摘要和待审草稿，不加载聊天工具或完整角色指令。支持明确 approve/revise/reject 文本协议，也兼容已发布的 JSON 决定；随意正文、空修改稿、超时、取消不得提交。原文在期间被编辑或删除仍使审阅失效。

草稿与审阅要求第一人称。摘要目标800至1600字，复杂内容至多2400字；附录最多6条近期原话、每条240字。自动摘要互斥，失败冷却5分钟；上一份摘要后不足3次用户发言且未接近硬窗口上限时不再次自动压缩。手动操作不受冷却限制。

## 主动活动

持久化每个目标会话的下一次时间、目的和是否暂停。首次启用由设置的等待时间启动；之后由 companion_schedule 自行安排。服务10秒检查一次本地计划，不在检查时调用模型。到期但正在对话、通话或刚收到用户消息则延后。

活动使用正常 ChatServiceCore、同一角色和工具权限；临时内部轮次不进入用户聊天，不朗读内部步骤。工具与学习结果通过资料库/待办显式保存。用户发送新消息先取消本轮活动；发送前再次核对聊天末尾并过滤近期重复内容。最多12次普通工具、5分钟；调度工具不计入普通工具次数。

日志每会话保留最近300条，包括唤醒、延后、工具结果、安静、通知、异常、安排及XC回执。学习选择控制主动目标，不扩大已有权限。来电在同一用户消息之后最多请求一次。

## XC

已核对 xinchao-nian a38a0a3 的 MCP 协议：xinchao_context 会结算状态/领取信号，版本变化不代表互动被写入。分类器未开启或在默认8分钟间隔内时，仅 exchange 可能没有互动类型；tone 与互动效果分开结算。客户端新增 interaction_type，并要求真实 exchange、稳定事件 ID；关系互动不得捏造她的回应。

同一请求内缓存自动读取，get 返回注明含义的快照；新一轮对话重新同步。互动回执单独保存与展示。未获得用户手机上的 MCP 授权，未向线上XC写入测试事件，也未部署XC。服务端实际状态需结合新日志验证。

## 资料、待办和通话

角色资料库按关键词匹配并随机选最多3条180字预览。完整正文仅显式获取。旧保留记忆按稳定ID迁移，超过单条长度的内容分段保存；保留原始存储以防迁移中断，重复迁移不产生副本。待办沉淀与移除在同一原子写入完成。

实时声音与语音窗口保持原有边界。手动模式仅在点开始后保存音频，忽略环境静音判停；发送或60秒上限结束一段。转写处理和AI回应期间暂停分段采集，界面状态与发送按钮同步。静默心跳在手动录制时抑制，摄像头回调不得抢走未发送录音。

## 验证门槛

新增协议、迁移、日志上限、待办沉淀、相关资料预览、重复通知、唤醒时间边界及手动/实时音频边界单元测试。Android CI 同时运行单元测试和APK构建；固定签名在构建前后均验证，成功后才发布应用内更新。

真机待验：三种音频后端的分段发送、嘈杂环境实时切换、后台被系统限制、真实MCP权限弹窗、当前模型的压缩审阅。编译成功不能替代这些验证。
