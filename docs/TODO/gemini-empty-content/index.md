# Gemini 空内容请求与异常隔离

设备 `1.12.2-pc.1+86` 的 2026-11-10 崩溃记录为 Gemini HTTP 400：缺少 parts。日志保留了崩溃栈和重启后的启动记录，没有失败请求正文，因此不能确认是哪条消息触发，也不能归因于尚未发布的六批改造。

已定位的请求路径：媒体引用仍在而缓存内容不可读取时，buildPartsArray 会得到空数组；空白或只含已移除思考标记的历史会生成空 text。旧实现仍把它们作为 Content 发送。

本修复只调整请求投影，不删除聊天记录。无内容的历史条目不序列化；当前输入没有可用内容时，在 HTTP 前明确拒绝，保留当前输入供用户处理，不填造消息、不重发旧问题、不重试同一个非法请求。最终 JSON 也校验 contents/parts，覆盖自定义参数改写后的实际请求。

异常隔离复用 PR #53–#58 依赖链已实现但尚未发布的 collectResponseReaders 边界及对应测试，使读流子协程错误通过本轮结果报告，不逃逸到宿主全局异常处理。此补丁不包含六批内部状态功能。后续合并六批时保留同一实现，不再次建立异常处理入口。

范围：Gemini 请求序列化、发送前内容验证、聊天读流错误隔离、必要字符串与回归测试。不改引擎、记忆、角色配置、私域页面或发布工作流。

新增回归用例覆盖：缺失历史媒体、当前缺失媒体、空助手历史、仅系统指令、工具结果、纯媒体请求、最终参数覆盖、发送前拒绝且零网络/零重试、子读流错误和取消。尚未完成测试验证，真实设备原始请求仍待复验。
