# 压缩与工具调用连续性

当前工具结果超过压缩阈值会终止对话，发送时的异步压缩又与回复并行，摘要源可能尚未完成。手动插入摘要没有继承上一份摘要，最近对话也全部依赖有损摘要。

本次改为按聊天排队：当前回复、工具链和消息落库完成后才读取压缩源。等待和压缩期间不允许下一轮越过分界。阈值只提出压缩请求，不中断工具后续回复，不在压缩完成后额外续写一轮。

摘要仅覆盖明确的历史前缀，最近两轮原文保留在摘要之后。历史不足时保留最近一轮；没有可压缩的旧轮次时保持原文。手动插入继承已有摘要；提交时在聊天写锁内检查来源和边界。

群聊没有新用户消息时，以成员请求的 sentAt 识别完整轮次；同一请求的文字片段与工具结果不拆开。手动压缩期间，下一位群成员等待压缩完成或取消后再发言。其他聊天不受该等待影响。

范围：消息协调、工具结果续聊、手动摘要、历史写入及对应回归测试。维持现有包名、签名、数据库与软件内更新流程。

步骤：

1. 修复压缩调度与完整轮次等待。
2. 统一摘要前缀和保留尾部，验证旧摘要与来源边界。
3. 回归测试、Android 构建、检查覆盖安装签名并发布。

新增 15 项 SummaryContinuityTest，覆盖截图场景、完整轮次分界、旧摘要继承、来源变化、等待工具与落库、取消与重复触发，以及群成员等待。
