# 情侣游戏屋、AI 储物柜与通知中心：第一期

## 目标与范围

用户负责签发情侣券，AI 可以表达愿望、接收、保存、提出兑换申请，但不能代签或自动扣次。AI 可以创作、整理、保密和赠送自己的数字物品。

通知中心归每个助手自己管理偏好。软件实际安装版本、新游戏、未送出券、赠送券和兑换结果形成真实事件记录，保留已送达与已读的区别。

核心边界：长期保存绝不等于长期携带。券、物品、通知和历史故事不能无限堆入对话摘要、上下文和每轮提示词。

## 当前实现

- [DONE] 独立 SQLite 持久保存券、物品、通知、AI 偏好与版本观察记录。每行带角色归属，聊天窗口只选择助手，不决定归属
- [DONE] 用户制作券时先暂存并通知 AI；再次主动赠送才授予兑换权；AI 只能申请，用户确认互动完成才扣次；耗尽的券保持为纪念
- [DONE] AI 创建私人或公开物品，可切换可见性、送给用户；查看完整内容需要单独打开对应物品
- [DONE] OWN 通知偏好：主动唤醒、下次阅读、仅存档；用户关闭原有主动机制时不越过关闭状态
- [DONE] 复用 CompanionRuntime 串行唤醒通道：闲置时最多合并三条通知，单角色已有主动许可才尝试；中断后不自动重复执行模型操作
- [DONE] 真正模型请求最多接收三条新通知，每条只取短消息；标记已展示不等于已读；历史通过工具分页查阅
- [DONE] 助手房间新增「情侣游戏屋」「储物柜」「通知中心」入口，列表分页，物品正文按需打开
- [DONE] AI 工具只能作用于当前角色所属私聊；没有发行券、确认兑换的 AI 操作
- [DONE] 安装版本变化时仅根据实际 BuildConfig 生成更新提醒，不把仓库提交误认为已安装更新

## 数据与兼容性

新的数据库文件为 `companion_playroom.db`，不改动当前的引擎、记忆库、内部状态表或旧聊天摘要。未发布过此新数据库，因此初始结构无需迁移旧表。

完整物品正文只驻留数据库，工具按 ID 调取；列表每页 20 条；主动送给模型的新通知一次最多 3 条，消息限制 180 字且整批再限制 700 字。通知不会随聊天轮次重复加载全部历史，也不会复制到现有记忆存储。

用户可正常访问自己安装的软件数据；AI 私人抽屉仅实现应用界面的非公开显示，不保证对设备所有者的加密隔离。

## 最小验证路径

在同一助手的私聊打开房间，进入情侣游戏屋，创建一张券，核对通知中心生成未赠送消息。暂存状态不应在 AI 券夹里；赠送后应出现。让 AI 申请兑换，再由用户确认完成；券扣次，次数归零后保留纪念。

让 AI 创建一件私人物品，再改成公开并赠送；检查用户端公开展示和礼物记录。让 AI 调整通知偏好并确认下次通知行为。切换同助手不同聊天窗口数据应一致，切换其他助手不可看见私人物品。

在通知积累后，核对每轮只提供最多三条新通知，已展示通知不会无限重新注入；摘要不拷贝通知或储物柜正文。
