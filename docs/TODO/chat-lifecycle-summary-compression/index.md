# 消息结束状态与上下文压缩修复

## 问题与目标

用户报告消息存入后没有回复、发送与回复变慢、回复结束仍显示等待，要求将摘要的第二次 AI 审阅改为可关闭，并解决压缩后占用仍高、很快再次触发压缩的问题。

上传日志显示取消主动活动之后，后续普通发送在活动注册阶段被拒绝；也存在正文结束后较长的收尾与下一轮输入估算。该日志未记录一次实际压缩，压缩问题需要依据当前代码和针对性回归验证。

## 作用域

1. 修正主动活动取消与发送终态的归属、释放和通知，避免旧回合占用新回合。
2. 将回复终态与非交互收尾分离，检查是否有重复或串行的昂贵输入准备。
3. 在上下文摘要设置新增真正控制二次 AI 审阅的持久化开关，默认延续现有行为。
4. 校正摘要保留范围、压缩预算及压缩后输入统计，保留原始聊天与主体资料。
5. 修复主动联系与自主探索唤醒的终态通知和具体调度提示，区分已预约、明确暂停、没有新约与中断，保留原预约供显式恢复。
6. 执行对应回归验证，使用现有构建与发布流程完成合并及应用内更新发布。

## 验证要求

- 主动活动取消后能发送新消息，旧活动结束不能覆盖新活动。
- 成功、失败与取消都有正确终态；最终可见回复结束后不等待无关输入预估。
- 关闭 AI 审阅后不再调用审阅模型，重新开启仍保留审阅行为。
- 压缩保留必要的近期上下文并实际减少待发送历史，不因旧统计立即重复触发。
- 发布产物对应本次验证通过的提交。
- 中断不会被展示为主动休息，后来的新预约或明确取消不会被旧轮次的收尾覆盖。
