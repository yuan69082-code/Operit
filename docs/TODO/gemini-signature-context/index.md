# Gemini 接口切换与空回复修复

## 问题

同一聊天窗口从 Vertex AI 配置切到 Google Gemini API 配置后，请求仍携带旧工具轮次的 thought signature。已确认旧请求成功，新请求返回 `Corrupted thought signature`；签名内容并未被截断。

终态异常在增强聊天层和共享流边界没有完整传到界面，空回复仍被保存为已完成。模型配置的 Tool Call 测试另有独立问题：测试手工构造了一段没有签名的助手调用历史，尚未真正请求模型调用工具就提交工具结果，触发缺少签名错误。

## 修改范围

请求准备沿用既有 ChatMessage 中的 provider 和 modelName，放进 PromptTurn 的请求内元数据，并在工具消息拆分时保留。Gemini 在合并相邻历史块之前，仅移除已完成旧轮次中来源明确不匹配的签名标签。正文、工具参数和工具结果继续发送，数据库中的原始消息不变。

最新非空 USER 或 SUMMARY 之后属于当前轮；TOOL_RESULT 不开启新轮。当前轮签名、同源历史签名及来源不明的历史均保留。这里不尝试更换来源继续一个正在执行的工具轮，也不伪造签名或跳过校验。

终态异常经首轮、工具续答和共享流完成状态传回现有错误展示。失败不能进入成功通知和完成落库分支；已有部分输出仍保留，首包前的空占位不写入聊天记录。合法的内部状态更新仍按原有流程提交。

工具连接测试使用同一个服务实例完成两轮请求。首轮要求真实调用固定的 `echo(text="ping")`，仅执行这个本地回声操作；将完整助手输出（含签名）与真实结果送回第二轮。只有收到可见续答且没有继续调用工具，才确认成功。未验证、接口失败和用户取消保持各自语义。

## 回归范围

针对 Vertex 到 Google 的历史迁移，验证原始记录不变、调用与结果保留、当前多步工具轮签名不丢失，以及消息拆分和相邻块合并前的来源处理。另覆盖同源历史、未知来源和更换模型。

工具探测覆盖完整签名回传、异常或多余工具、无可见续答、两轮异常与取消。错误展示覆盖共享流记录的失败、半截输出、空输出和正常静默状态更新。具体执行结果记录在对应 PR 的检查中。

## 边界

历史只保存了 provider 和 modelName，不能据此判断同 provider、同模型而仅修改 endpoint 或凭据的情况，本次不为这些未记录的信息作推断。已经产生的旧空消息不作批量清理。

Google 的 GenerateContent 当前轮签名规则见[官方说明](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures)。同源正常请求继续保留原有签名；这次变更针对已知来源变化，不扩大为对所有跨模型签名兼容性的结论。
