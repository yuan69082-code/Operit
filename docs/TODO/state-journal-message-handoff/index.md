# 状态提交校验与活动结束后的消息交接

2026-11-18 的设备日志在 SubjectLife.rest 读取状态时报告“事件提交标识冲突”。旧校验使用 Number.toString，流式存储保留的 1.0 与 JSONObject 复制后的 1 会产生不同摘要。

本次仅为事件提交引入带版本的数值规范化摘要，不改变其他来源、报告及身份摘要。已有提交须与同一 frame 的有序归档版本完整匹配才能升级摘要；不重放状态、不删除记录，真实内容冲突继续拒绝。

消息队列原先在 250ms 等待前消耗空闲转换信号。队列变动重启 Compose effect 时，等待被取消且信号丢失。现在等候结束再消耗；等候期间追加消息也保留尚未消费的转换。

已增加数值往返、旧摘要升级、真实内容冲突拒绝、新版状态不被旧提交覆盖、助手隔离以及队列追加场景的回归用例。用户已明确授权兼容性检查、测试、构建直至发布。

核对 main@f139e52 的自由时间、梦境、状态材料预算与原有消息/活动入口：继续使用原生活调度和执行回执；休息仍需主体采用，日程配置不重写睡眠选择；当前休息控制卡仍在统一材料预算内；外部引擎窗口的权威边界不变。没有调整候选采用、人格/关系原文、自动唤醒频率、模型配置、包名或签名。
