# 手机入口与功能协调

原手机发送流程会先读取角色模型、自动摘要，再生成回答。引擎关联入口需要在这些步骤前分流，原始用户文字与来源单独留存；不把人设、摘要或工具包装文本作为主体身份发送。

关联后的软件独立回复、主体记忆写入及摘要决策停止。后台自主任务默认不发起；用户可允许它们形成辅助事件，但不能自行调用模型替主体决定。原偏好值保留，解除关联后仍可使用。

手机与软件感知保留原来的授权范围，并增加是否向关联主体提供该类事件的开关。关闭连接期间不新增投递。软件观察仍只属于指定观察助手，不扩散给群内其他主体。

原生入口有本机持久记录与同步状态；发送到电脑桥梁只代表平台接收，不代表引擎已收到。界面必须区分这两个状态。

## 使用入口与当前能力

在某个助手的私聊打开“状态与资料 → 引擎连接”，填写电脑共享服务地址与共享 Token，再保存已有主体标识。手机只持有共享服务 Token；引擎服务令牌在电脑端保存。开关、消息、群聊、手机、软件、通话与辅助事件授权独立保存。

关联后，发送入口在软件模型选择之前分流，重新生成和自动压缩也不调用软件模型。群成员各自检查关联；不要求引擎主体选择软件里的模型。包含引擎成员的群聊当前只接收文字，附件保留并明确提示协议未接通。

原始文字先进入本机事件记录，再同步到电脑。后台同步依附现有前台服务，每轮最多处理五条待同步记录；关闭连接停止新增事件。撤权与解除关联的控制记录也持久化，联网后优先同步。离线撤权不能声称电脑已经收到；界面明确显示这一点。解绑重绑生成新的入口标识，旧记录不转给新主体。

手机、软件感知继续同时检查原有观察授权与引擎事件授权。软件自主活动不会再执行自身模型；允许的辅助请求只记为事件，不把保存事件算作任务完成。原偏好保留，已经暂停或消费的旧预约不会在解绑后自动重演。

尚未实现的正式联调内容包括：附件及媒体协议、群聊完整事件流与成员身份协商、真实主体最终表达回填到原生聊天、引擎请求的平台模型或工具执行、后台唤醒的正式回执。当前不会显示模拟回复，也不提供伪造的“已接通”状态。

[DONE] 原生连接准备与本机行为隔离；真实主体通信仍等待正式协议。
