# 连接与投递

原共享服务只有全局模型配置，直接把模型流显示为回复。本批增加独立引擎连接配置及按软件入口保存的主体关联。关联只是目标标识，不是引擎签发的身份或已完成的绑定确认。

连接默认关闭，关闭不等于解除关联。关联仍在时，软件不自行生成主体回复。用户显式解除关联才能恢复原有软件模式。修改关联目标时不把旧队列转交给新主体。

原 Vio Live 的本机 HTTP 传输及 JSON 规范化迁入 desktop/src/engine/vendor。记录迁入来源。引擎内部模型与生命周期没有控制接口；业务后端不会因接入而自动执行模型或工具请求。

事件是软件事实，包含稳定事件 ID、入口、主体、时间、类型、载荷哈希。发送前落盘，处理中重启记为结果未知；未知先查询，不自动重发。关闭或撤权后停止新投递，已发出的未知请求不能伪装成取消成功。健康检查只证明服务可达，不证明鉴权、主体绑定或协议兼容。

正式协议没有确定前，事件标记 awaiting_protocol。普通消息、群聊消息、感知、通话与辅助请求分别标识，不把后台事件伪装为用户发言，不把全部私聊历史拼进群聊。

## 本批已落地

电脑端由共享服务设置进入“引擎连接”。服务连接与聊天入口关联分开保存，均默认关闭。服务令牌不在读取配置接口中返回。事件持久化到独立的 engine-window.json，普通会话配置与记录不迁移、不改写。

引擎地址继续遵守旧接口的本机 HTTP 边界，只允许 127.0.0.1。当前只复用传输与规范化模块，不搬运固定测试主体、旧模型执行器或旧前端的主体状态容器。
