# 连续性引擎的外部窗口

引擎是独立持续运行的主体，内部模型、人格、记忆、状态演化、时间与唤醒由引擎拥有。Vio Life 提供交流窗口、平台事实与已授权资源，不管理引擎生命周期，不替主体选择内部模型。

目前手机原生聊天和电脑共享服务各自直接调用模型。Vio Live 的旧连接实现使用固定测试身份，通用 Subject Runtime Port 仍未接线。引擎当前公开的本机 HTTP 入口不能确认任意正式主体绑定；模型 v2、睡眠回执也与旧前端不同。因此本批完成软件侧准备，不能声称正式主体已接通。

只修改本仓库。引擎源码只读，不启动引擎、不初始化主体、不写入引擎数据。参考 Vio Live 的通信、规范化哈希和可靠投递设计，来源固定在 1eaeef29c6e09156fa0350392f0acb95f9a17c96；引擎核对版本 c2c6beb9a4b4e011adb2b1abdc7840f95f957a15。

## 实施范围

1. [连接与投递](1-connection.md)：默认关闭的连接、稳定入口绑定、授权、持久事件收件箱及协议边界；保留原有模型配置。
2. [手机入口与功能协调](2-android.md)：私聊与群聊按所属主体路由；连接关闭仍保留绑定，禁止静默切回模型；手机与软件感知分别授权。
3. [验证与接续](3-verification.md)：仅在本项目的模拟服务中验证；记录真实验证结果和正式联调前置条件。

本批不创建或迁移引擎主体，不复制测试身份，不把应用内部事件格式宣称为引擎已接受的协议。当前生产适配器仅允许显式健康检查；事件可以保存在软件侧，标为等待正式协议。模型和工具执行请求不自动执行。未来接入正式适配器时，沿同一身份、权限、持久化和回执边界继续，不另建主体账本。
