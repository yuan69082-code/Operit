# 连续声音感知与同时收音播放

音频分析通话原先录一段、分析、生成与播放之后才重新收音。没有原话的片段只作背景保存，不能触发主体决定是否回应。本次把当前音频分析通话改为独立采集、顺序分析、主体回复三条协程路径。转写通话和原生音频通话保持原有输入方式。

采集使用同一个16kHz单声道AudioRecord，含约300毫秒起始缓冲。声音门限为0.004 RMS，既包含说话也包含非语言声音；低于门限不会自动上传。600毫秒低音量可分段，连续声音最长约3秒必须交付窗口，因此不等待全部声音停止。静音期间丢弃采集数据，不向分析器交付新窗口。静音切换递增采集代次，排队或正在分析的旧窗口不会在解除静音后重新交付。

每个窗口保留不可变时间与低音量区间。分析请求与播放并行，短窗口末尾不视作用户说完。新增sound_activity和sound_events字段，保留听到的呼吸、笑声、叹气等现象与来源不确定性，不推断行为、关系或具体活动。声音参考为快照，分析中的原文件不会因用户重置参考而被删掉。

最多4个待分析窗口和8个待处理观察，避免接口慢导致无限排队。跟不上时删除较旧窗口或观察，并在通话界面显示跳过提示。此方案不承诺逐帧无丢失。能确认的原话正常进入当前会话；只有声音的观察隐藏，不刷用户聊天气泡，主体可以回复或输出quiet继续听。仅将确实产生的观察回复补记为AI通话记录。

录音源改为VOICE_COMMUNICATION，尝试启用系统AcousticEchoCanceler。共享队列和系统TTS在音频分析通话内使用语音通信播放属性。增加普通权限MODIFY_AUDIO_SETTINGS，在释放录音器后恢复之前的音频模式。没有可控AEC时明确显示耳机建议，不声称回声已经消除。分析器收到窗口内扬声器播放文字作为疑似回声参考，无法区分则保持不确定，不仅凭字句相同删除近场发言。

静音清理尚未提交的观察与保留音频；挂断、初始化失败、分析失败均停止采集和分析任务。后台采集/分析异常转为可见通话错误，不从子协程泄漏为未处理异常。打字和摄像头仍使用同一通话角色、队列与回复链。

本次不是WebSocket原生音频流，也不替换主体模型。约3秒窗口之后仍有音频模型、主体模型和TTS网络处理时间。主体正在完成一次回复时，新声音继续采集和分析，新的主体决策在当前回复结束后进行；手动打断入口保留。持续有声音时分析请求与费用增加，轻微声音和环境声仍可能受设备音频处理影响。

已审阅采集分段、静音、队列丢弃、参考快照、语音播放、无文字观察、打字以及挂断清理的代码路径。按仓库约定未主动执行本地编译或测试命令；由提交触发现有自动工作流验证编译。实际回声消除、收音灵敏度与端到端延迟必须手机实测。
