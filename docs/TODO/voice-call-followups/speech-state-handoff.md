# 已转写录音被说话状态阻塞

用户报告第一段通话录音可以发送，第二段生成 retained-live 文件后没有进入 AI 轮次。该文件仅在音频分析产生非空 userText 后复制，因此文件存在说明该片段已取得转写，后续还需要排队、等待说话状态释放和主体投递。

采集在 IO 线程运行，分析消费在控制器协程运行。此前 publishSpeechState 在切换到主线程之前计算 Boolean，再交给主线程回调。采集排队的 true 快照可以晚于分析完成后的 false 到达，令 speechTurnActive 停留在过期状态；takeHeardInput 会因此拒绝取出已分析片段。手动提交后停止采集时尤其缺少后续状态通知来纠正它。

改为在主线程读取采集状态和待分析计数，再直接发布给控制器，消除跨线程传递旧快照的窗口。保留现有语音结束判断、队列和输入接口。增加状态变化、分析入队和主体取队日志，只记录状态、时间和文件名，不记录正文。
