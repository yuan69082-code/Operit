# 通话等待、结束通知与声源修正

原流程在音频正文结束后仍等待聊天显示和落库，挂断只添加历史记录，悬浮窗只在小窗与紧凑条之间切换。用户端旁人声音还可能被聊天模型误认成通话另一端。

本次在原通话方案上修正以下行为：

- 通话正文完成回调即可结束语音轮次，恢复收音；下一次模型请求单独等待上一轮落库完成，避免并发覆盖。录音和转写静默分段为700毫秒，长停顿可能因此拆成两轮。
- 用户挂断已经接通的电话，通过绑定会话和角色的正常消息链发送一次“通话结束”，关闭音视频后以文字聊天回应。AI挂断、系统停止、未接通取消仍保留各自事件记录。发送失败会记录错误并提示。
- 小窗新增完整屏幕尺寸与原小窗尺寸切换，临时隐藏仍不结束通话。
- 分析器、结构化上下文和聊天状态一致说明所有声音来自用户端麦克风。旁人为身份不明，只给出可能的性别、年龄和音色印象，不推断为AI或具体人物。用户原话中的人名不删除。
- 未匹配用户的片段保留旁人原话及声音特点，供随后用户发言参考，仍不独立触发回复。

作用域为VoiceCall相关录音、分析、控制与悬浮窗，以及ChatTurnOptions、ChatViewModel和消息协调/处理链。

已检查修改文本、调用签名、分段门限和单次结束消息路径。当前执行环境不可用，未在本地运行编译或手机验证；提交后由既有Android Build工作流验证编译。音频网络服务等待、扬声器播放期间暂停收音、首句候选声音识别的局限仍存在。
