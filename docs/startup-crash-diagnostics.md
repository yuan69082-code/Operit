# 首页无法打开时导出日志

长按桌面图标，进入「数据救援」，点击顶部「导出应用日志」。保存位置由页面显示，沿用 Download/operit/operit_log_时间.txt。无需进入首页、安装文件管理器或导出全量快照，不修改聊天、模型配置或数据库。

导出包含现有 operit.log，以及存在时的 last-crash.txt。后者记录最近一次由全局 JVM 异常处理器捕获的异常、发生时间、应用版本、线程和进程 ID；在启动崩溃页及退出前同步写入，普通日志重置不会删除它。旧异常单独标注文件名和发生时间，不能当成本次启动的异常。

这是诊断入口修复，不是已确认的 +63 首页退出原因或恢复使用的保证。+63 相比 +60 的生产代码只改变 Vertex 请求地址处理；现有证据尚未确定首页退出位置。救援页的 SQLite 完整性检查成功也不等于主界面初始化成功。

全局处理器只捕获安装处理器之后的未捕获 JVM 异常。原生崩溃、系统杀进程、处理器安装之前的异常不保证有 last-crash.txt；保存失败会写入系统日志。现有日志可能含聊天及请求内容，只在用户主动导出时写入下载目录，不自动上传。

验证：静态差异检查；完整 Kotlin 编译和现有回归测试交由 CI。仍需要设备上的日志来定位原始问题。
